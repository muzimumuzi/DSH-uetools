# 系统接口

## 执行控制台指令 `system.run_console_command`
在当前 World 上执行任意控制台指令。（旧别名 `cmd.exec_console` 已于 2026-09-16 删除。）

### 请求（JSON-RPC）
```json
{"ver":"1.0","type":"req","id":"cmd1","method":"system.run_console_command","params":{
  "command":"stat fps"
}}
```

### 响应
```json
{"ver":"1.0","type":"res","id":"cmd1","code":200,"result":{
  "result":"OK"
}}
```
- 若执行失败，`code` 为 500，`result.result` 为 `"Failed"`。

### 说明
- 支持 Editor/PIE/Standalone（内部会根据是否有 GEditor 选择世界）。
- 指令需确保在当前模式下有效；部分只读指令（如 `stat` 类）可直接使用，修改型指令需谨慎。

## 插件管理 `system.manage_plugin`
查询或修改虚幻插件的启用状态，适配 GLB/GLTF/USD/Python 等需要插件支持的场景。

### 请求
```json
{"ver":"1.0","type":"req","id":"plugin1","method":"system.manage_plugin","params":{
  "plugin_name":"GLTFImporter",
  "action":"Query"
}}
```
- `action` 取值：`Query`（查询状态）、`Enable`（启用）、`Disable`（禁用）。默认 `Query`。

### 响应
```json
{"ver":"1.0","type":"res","id":"plugin1","code":200,"result":{
  "plugin_name":"GLTFImporter",
  "is_enabled":true,
  "requires_restart":false,
  "friendly_name":"glTF Importer",
  "uproject_path":"D:/Demo/Demo.uproject",
  "uproject_state":"enabled",
  "uproject_verified":true,
  "default_enabled":false,
  "message":"Plugin enabled in .uproject (verified on disk). Restart required."
}}
```

### 说明
- 找不到插件时返回 `code` 404。
- 状态发生变化时 `requires_restart` 为 `true`，需提示用户重启编辑器。
- 典型插件：`GLTFImporter`、`DatasmithGLTFImporter`、`USDImporter`、`PythonScriptPlugin`。

### 落盘与回读校验
`Enable`/`Disable` 会改写项目的 `.uproject`，做三件事，缺一件都不算成功：

1. `IProjectManager::SetPluginEnabled()` —— **只改内存**，引擎头文件原话是
   "does not save to disk"；
2. `IProjectManager::SaveCurrentProjectToDisk()` —— 落盘（老版本漏了这一步，
   于是回了成功但 `.uproject` 里什么都没有，用户白重启两次编辑器）；
3. 重新从磁盘解析一遍 `.uproject`，确认那一条真的在里面。

第 3 步的结果放在 `uproject_state`（`enabled` / `disabled` / `absent` /
`unreadable`）和 `uproject_verified` 里。校验没过时返回 `code` 500，
`message` 说明磁盘上实际是什么状态。

`absent` 不一定是错的：目标状态和插件默认状态一致时，UE 会主动把条目删掉
（禁用一个本来就默认关的插件，正确结果就是文件里什么都没有）。所以响应里
一并给出 `default_enabled`，调用方据此判断。

## 获取性能统计 `system.get_performance_stats`
返回当前采样周期的平均 FPS 以及各线程/GPU 的耗时（毫秒）。

### 请求
```json
{"ver":"1.0","type":"req","id":"perf1","method":"system.get_performance_stats","params":{}}
```

### 响应
```json
{"ver":"1.0","type":"res","id":"perf1","code":200,"result":{
  "fps": 118.3,
  "frame_ms": 8.45,
  "game_thread_ms": 3.12,
  "render_thread_ms": 2.76,
  "rhi_thread_ms": 0.80,
  "gpu_ms": 5.10
}}
```

### 说明
- 数据来源：引擎统计全局均值（`GAverageFPS/GAverageMS/GAverageGameTime/GAverageDrawTime/GAverageRHITTime/GAverageGPUTime`），需引擎已运行一段时间以形成均值。
- 各字段单位均为毫秒；`fps` 为帧率。若统计尚未有效（刚启动），数值可能为 0。
- **UE 5.0 限制**：在 UE 5.0 中，`render_thread_ms`、`rhi_thread_ms` 和 `gpu_ms` 将始终返回 0，因为这些统计变量未通过 `ENGINE_API` 导出，插件无法直接访问。这是引擎版本的限制，不是插件的问题。
  - 在 UE 5.1+ 中，这些值可以正常获取。
  - 如需在 UE 5.0 中查看这些统计信息，请使用控制台命令：
    - `stat unit` - 显示所有线程和GPU时间
    - `stat scenerendering` - 显示场景渲染统计
    - `stat rhi` - 显示RHI线程统计
    - `stat game` - 显示游戏线程统计

## 采样一段时间的帧时序 `system.capture_perf_trace`

`system.get_performance_stats` 是滚动平均值的快照，容易漏掉偶发尖峰。这个命令用引擎自带的
CSV Profiler（`FCsvProfiler`）连续记录 `duration_seconds` 秒，逐帧记 FrameTime /
GameThreadTime / RenderThreadTime / RHIThreadTime / GPUTime，回百分位统计。

**异步**：立即返回不会，响应在 `duration_seconds` 秒（加内部宽限期）之后才发。

### 协议定义

```json
{
  "method": "system.capture_perf_trace",
  "params": {
    "duration_seconds": 10,
    "gpu_stats": false
  }
}
```

`duration_seconds` 会被夹到 1–120 之间。`gpu_stats` 打开时会设置 `r.GPUCsvStatsEnabled 1`
（有额外开销），不会在采样结束后自动关回去。

### 响应

```json
{
  "code": 200,
  "result": {
    "ok": true,
    "csv_path": "D:/MyProject/Saved/Profiling/CSV/Capture_2026-08-30-...-0.csv",
    "frame_count": 612,
    "requested_duration_seconds": 10,
    "actual_elapsed_seconds": 10.1,
    "gpu_stats_enabled": false,
    "stats": {
      "FrameTime": { "avg": 16.6, "min": 10.1, "max": 42.3, "p50": 16.0, "p95": 24.8, "p99": 38.1 },
      "GameThreadTime": { "...": "..." },
      "RenderThreadTime": { "...": "..." },
      "GPUTime": { "...": "..." }
    },
    "avg_fps": 60.2,
    "p99_fps": 26.2,
    "worst_frame": { "FrameTime": 42.3, "GameThreadTime": 12.1, "RenderThreadTime": 8.0, "GPUTime": 20.5 },
    "bottleneck": "GPU",
    "idle_sample": false,
    "note": "采自编辑器，不等于打包后的运行表现。要评估实际性能应在 PIE 或独立运行下采集。"
  }
}
```

### 列名怎么确定的

不是猜的。`FrameTime` 定义在 `CsvProfiler.cpp`，`GameThreadTime` / `RenderThreadTime` /
`RHIThreadTime` / `GPUTime` 定义在 `LaunchEngineLoop.cpp` —— 都是不需要任何 category 开关就会写的
全局 stat，5.0–5.8 逐版本核对过源码，一致。`RHIThreadTime` 只在有 RHI 线程时才出现，缺了就
不在 `stats` 里出现，不补 0。

### 已知边界

- 只有默认关闭压缩（`csv.CompressionMode` 保持 -1 或 0）时才能正确解析。如果本机把它强制设成
  `1`，会拿到 `.csv.gz` 而不是明文 `.csv`，工具会明确报错而不是解析出乱码。
- 一次只能有一个采集在跑——不管是这个命令、别的工具还是控制台 `csvprofile start` 触发的。

## 触发一段 Unreal Insights trace `system.capture_insights_trace`

只负责录制，不负责分析。用 `FTraceAuxiliary::Start(EConnectionType::File, ...)` 直接指定
目标文件路径（不依赖 Trace Store，位置由我们自己定），录够时长后 `Stop()`，确认文件落盘，
把路径交出来。

**异步**：响应在 `duration_seconds` 秒 + 2 秒宽限期之后发。

### 协议定义

```json
{
  "method": "system.capture_insights_trace",
  "params": {
    "duration_seconds": 10,
    "channels": "cpu,gpu,frame,bookmark"
  }
}
```

### 响应

```json
{
  "code": 200,
  "result": {
    "ok": true,
    "utrace_path": "D:/MyProject/Saved/Profiling/UnrealAgentLink/Capture_20260830_120000.utrace",
    "channels": "cpu,gpu,frame,bookmark",
    "requested_duration_seconds": 10,
    "actual_elapsed_seconds": 12.0,
    "note": "这是原始 trace 文件，本命令不解析它。..."
  }
}
```

### 为什么没有完成回调

`FCsvProfiler` 有 `OnCSVProfileFinished` 委托，这里没有对应写法——因为
`FTraceAuxiliary::OnTraceStopped` 是 **5.1+ 才加的静态成员**，5.0 上不存在（连
`IsConnected()` 都没有）。所以这个命令不依赖任何版本相关的完成信号：`Stop()` 之后固定等 2 秒
宽限期，再检查文件系统确认文件真的存在，9 个版本行为一致。

文件是流式写的普通文件（不像 CSV Profiler 有一步整体压缩+落盘），2 秒宽限期足够。
