# 关卡工具接口

## 关卡资产开销排行 `level.query_assets`

按资产聚合当前关卡（或选中集）里的静态网格，回「哪几个最贵」以及为什么。

### 为什么按资产聚合

同一个网格摆五百份，旧版本回五百行一模一样的数据；真正该看的那个数
——「这个网格在关卡里一共画了多少三角形」——一次都没出现过。
现在一个资产一行，带出现次数、实例数和总面数。

### 协议定义

```json
{
  "method": "level.query_assets",
  "params": {
    "scope": {
      "type": "Level | Selection",   // 只有这两个。没有 ContentBrowser
      "path": "/Game/Props"          // 可选
    },
    "conditions": {
      "min_triangles": 50000,        // 单份面数门槛
      "min_instances": 100,          // 至少摆了多少份
      "missing_collision": true,
      "nanite_enabled": false,
      "shadow_casting": true,
      "class_filter": "StaticMeshActor"
    },
    "sort_by": "TotalTriangles | TriangleCount | InstanceCount | ResourceSize",
    "limit": 20
  }
}
```

`sort_by` 默认 `TotalTriangles`（单份面数 × 实例数）。

### 响应

```json
{
  "code": 200,
  "result": {
    "count": 20,
    "matched_assets": 137,
    "actors_visited": 4210,
    "truncated": true,
    "assets": [
      {
        "name": "SM_Grass_Clump",
        "path": "/Game/Foliage/SM_Grass_Clump.SM_Grass_Clump",
        "type": "StaticMesh",
        "stats": {
          "triangles": 462,
          "total_triangles": 1940400,
          "instance_count": 4200,
          "actor_count": 3,
          "resource_bytes": 184320,
          "lod_count": 1,
          "material_slots": 1,
          "nanite": false,
          "missing_collision": true,
          "shadow_casting": true,
          "max_texture_edge": 4096,
          "max_texture_pixels": 16777216,
          "texture_bytes": 22369621
        },
        "sample_actors": ["Foliage_01", "Foliage_02", "Foliage_03"]
      }
    ],
    "not_ranked_by_class": {
      "PointLight": 240,
      "SkeletalMeshActor": 12
    }
  }
}
```

### 三个容易读错的字段

- **`resource_bytes`** 是引擎估算的常驻资源大小，**不是磁盘文件大小**。
  想要磁盘体积用 `content.asset_ranking`。
- **`not_ranked_by_class`** 是**没进排行**的 Actor 类型计数。灯光、骨骼网格、
  贴花都有开销，但没有和三角形可比的指标，硬塞进同一个排行只会得出错误结论。
  要逐个看它们，用 `content.asset_ranking` 按类型查。
- **贴图字段只有返回的这几条才有**。算贴图要走材质取贴图对象，是整个流程里
  唯一贵的一步，所以排序截断之后才算。也因此**没有按贴图内存排序**这个选项
  ——全工程按贴图内存排行走 `content.asset_ranking`，那边读注册表标签，不用加载。

### 已经删掉的参数

这四个参数曾经出现在协议里，但插件只是把它们读进变量，**从未参与过筛选**：
`min_texture_size`、`max_texture_size`、`shader_complexity_index`、`min_radius`。
宣传一个不生效的筛选条件比不支持更糟——调用方会以为「筛过了、没有」。

同样删掉的还有 `scope.type: "ContentBrowser"`：插件对它一律回 400，
而这个工具叫「找重资产」，查整个工程才是最自然的用法，于是每次都选它、每次都失败。
整个工程的排行现在有专门的命令。

### 高级玩法示例

- **铺得到处都是的东西**：
  ```json
  { "conditions": { "min_instances": 500 }, "sort_by": "TotalTriangles" }
  ```
- **高面数且没开 Nanite**：
  ```json
  { "conditions": { "min_triangles": 100000, "nanite_enabled": false } }
  ```
- **碰撞体检查**：
  ```json
  { "scope": { "type": "Selection" }, "conditions": { "missing_collision": true } }
  ```
- 这是接口契约文档，具体查询/统计逻辑需后端实现（如三角面数、贴图尺寸、Nanite 状态、碰撞体检测、材质复杂度等）。可分阶段支持：先实现核心指标，再逐步补齐高级字段。

## 批量组织Actor到文件夹 `level.organize_actors`
批量将场景中的Actor归类到指定的世界大纲文件夹，支持按类名过滤。

### 协议定义
```json
{
  "method": "level.organize_actors",
  "description": "批量将场景中的Actor归类到指定的世界大纲文件夹。",
  "params": {
    "folder_path": "Lighting/Indoor",    // 必需：目标文件夹路径
    "filter": {                          // 可选：Actor过滤条件（与actor.get的filter格式相同）
      "class_contains": "PointLight"      // 按类名过滤（包含匹配，忽略大小写）
    }
  }
}
```

### 简化用法（直接传class参数）
```json
{
  "method": "level.organize_actors",
  "params": {
    "folder_path": "Lighting/Indoor",
    "class": "PointLight"                 // 简化用法：直接传类名
  }
}
```

### 响应
```json
{
  "code": 200,
  "result": {
    "count": 5,                           // 成功设置的Actor数量
    "total_found": 5,                     // 匹配到的Actor总数
    "actors": [
      {
        "name": "PointLight_1",
        "class": "PointLight",
        "path": "/Game/Levels/MainLevel:PointLight_1",
        "folder_path": "Lighting/Indoor"
      }
    ]
  }
}
```

### 使用示例
- **将所有点光源归类到室内灯光文件夹**
  ```json
  {
    "folder_path": "Lighting/Indoor",
    "class": "PointLight"
  }
  ```
- **将所有聚光灯归类到聚光灯文件夹**
  ```json
  {
    "folder_path": "Lighting/SpotLights",
    "filter": {
      "class_contains": "SpotLight"
    }
  }
  ```
- **将所有静态网格Actor归类到道具文件夹**
  ```json
  {
    "folder_path": "Props/StaticMeshes",
    "filter": {
      "class_contains": "StaticMeshActor"
    }
  }
  ```

### 注意事项
- 此功能仅在编辑器模式下可用（`WITH_EDITOR`）
- 文件夹路径使用斜杠分隔，如 `"Lighting/Indoor"`
- 如果文件夹不存在，UE会自动创建
- 操作支持撤销（Ctrl+Z）
- filter参数支持与`actor.get`相同的所有过滤选项（class_contains, name_pattern, exclude_classes, property_match等）
